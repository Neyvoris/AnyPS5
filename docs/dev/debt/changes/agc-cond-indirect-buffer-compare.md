# libSceAgcDriver

## change (`sceAgcCbBranch`) runs only with the always-pass compare function

- A [COND_INDIRECT_BUFFER](../../../core/libs/prx/libSceAgcDriver/Execution/src/Driver/Queues/Submission.cpp) (`sceAgcCbBranch`) with a compare function evaluates `(*compareAddress & mask) <function> reference` over 64 bits when the queue executes the packet, not when the buffer is submitted (functions 1 to 6: less, less or equal, equal, not equal, greater or equal, greater; read through AMD's public PM4 packet layout, not measured on a console). A true result runs the first buffer; a false one runs the second buffer in mode 2 and nothing in mode 1. As with the always-pass compare, the branch does not return and replaces the rest of the buffer holding it. Function 7, a predicated packet, a branch inside a COND_EXEC range, a REWIND, a flip or a rendering wait inside either buffer still throw. Both buffers are copied at submit and the choice is made at execution, so a buffer the GPU rewrites after submission runs as copied; this is unverified on hardware. Modes 1 and 2 are still assumed to be the if-then and if-then-else modes of AMD's PM4 packet. [sceAgcCbBranch](../../../core/libs/prx/libSceAgc/Cb/src/Branch.cpp) does not check the compare address of an always-pass branch or the address of an empty buffer, as PPSA14632 passes an uninitialised compare address and a null else buffer of 0 dwords. Inside a COND_EXEC range the packets after a branch are still copied.
